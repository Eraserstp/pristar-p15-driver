# Анализ: драйвер принтера Pristar P15 для Linux Mint

Дата: 2026-11-09
Статус: анализ выполнен, протокол проверен на реальном устройстве, печать подтверждена (40 × 12 мм, gap).

## 1. Цель

Получить «обычный» принтер в Linux Mint:

- очередь CUPS с именем `Pristar P15`;
- принтер виден в «Настройки → Принтеры», в system-config-printer и в диалоге
  печати любого приложения (GTK/Qt/Chromium/LibreOffice/…);
- печать любых документов: приложение отдаёт PDF, CUPS растеризует его,
  драйвер кодирует растр в протокол P15 и отправляет по Bluetooth LE.

## 2. Что уже известно об устройстве (проверено на этом компьютере)

| Параметр | Значение |
|---|---|
| Имя в BlueZ | `P15_XXXX_BLE` |
| MAC | `AA:BB:CC:DD:EE:FF` |
| Тип | BLE (GATT), dual-mode чип с BR/EDR |
| Реклама | public address, RSSI ≈ −50 dBm |
| Сервис | `0000ff00-0000-1000-8000-00805f9b34fb` |
| TX (запись команд) | `0000ff02-…` — write / write-without-response |
| RX (ответы) | `0000ff01-…` — notify |
| CX (flow control/MTU) | `0000ff03-…` — notify |
| Альтернативный сервис | `49535343-fe7d-4ae5-8fa9-9fafd205e455` (TX `…8841`, RX `…1e4d`) |
| Ещё один vendor-сервис | `bef8d6c9-9c21-4c9e-b632-bd58c1009f9f` (read/write/notify) |
| MTU, выданный принтером | 240 → полезная нагрузка 237 байт |
| Реальный размер пакета для P15 | **95 байт** (ограничение прошивки клона) |
| Статус | `10 FF 40`, `1F 20 00` |
| Модель/прошивка/серийник | `10 FF 20 F0/F1/F2` |

Устройство — клон Marklife P15 (Pristar P15). Это подтверждают issue #3, #5,
#13 в проекте `tomLadder/thermoprint`: «Pristar P15 (clone of Marklife P15)».

## 3. Протокол L11 (используется P15)

Последовательность печати одной этикетки:

```
10 FF 10 00 02           установить толщину/плотность (для P15)
00 × 15                  wakeup
10 FF F1 02              enable
1D 76 30 00 wl wh hl hh  растровое изображение 1bpp, MSB-first
<данные>                 bytesPerRow × height
1D 0C                    позиционирование до следующего зазора (gap)
10 FF F1 45              stop
```

Для непрерывной ленты вместо `1D 0C` — `1B 4A 64` (подача 100 точек).

Управление потоком:

- принтер выдаёт кредиты уведомлением CX: `[0x01, N]`;
- отправляется ровно один пакет за тик таймера;
- тик для P15 — **30 мс**, размер пакета — **95 байт**;
- если кредитов нет 1 с, принудительно выдаётся 1 кредит (starvation recovery);
- завершение печати: `0xAA`, `0x4F` или `0x4B` на RX; клоны могут просто
  отключиться — это считается успехом.

Изображение: 203 dpi, 1 бит на пиксель, чёрный = 1, MSB-first, строки
выровнены по байту. Рекомендуется дизеринг Флойда–Стейнберга.

## 4. Интеграция с Linux/CUPS (проверено)

- Linux Mint 22.3, CUPS 2.4.7, cups-filters 2.0.0, `pdftoraster` присутствует.
- PPD-драйверы поддерживаются (CUPS 2.4), очередь появится в списке принтеров.
- **Бэкенды CUPS выполняются от пользователя `lp`** (проверено экспериментом),
  фильтры — тоже. `lp` не имеет прав на raw HCI.
- `lp` имеет доступ к системной D-Bus и может работать с GATT через `org.bluez`.
- Скрипты PPD-драйвера можно ставить как `Architecture: all` (Python 3.12).

### Проблема BlueZ и обход

Принтер в рекламе не выставляет флаг «BR/EDR Not Supported». Из-за этого
BlueZ (`select_conn_bearer()`) считает устройство dual-mode и при
`Device1.Connect()` выбирает BR/EDR. GATT при этом не поднимается, а соединение
завершается ошибкой `br-connection-profile-unavailable`.

Проверенное решение:

1. Создать LE-соединение на уровне HCI (команда `LE Create Connection`).
2. BlueZ получает событие `Device Connected (LE)`, создаёт GATT-объекты и
   выполняет discovery (`ServicesResolved = true`).
3. Дальше работаем с GATT через системную D-Bus (`StartNotify`, `WriteValue`).
4. Соединение живёт после выхода помощника; по завершении задания — `Disconnect`.

Так как `lp` не может открыть raw HCI, нужен маленький helper
`p15-leconnect` с файловой capability `cap_net_raw+ep`. Проверено:
копия `hcitool` с `setcap cap_net_raw+ep` успешно создаёт LE-соединение от
пользователя `lp`, после её выхода связь и GATT остаются доступны.

Альтернатива — root-демон; она избыточна для первой версии.

### Замечание по уведомлениям

На тестовых запросах (`10 FF 40`, `1F 20 00`, `10 FF 20 F0`) принтер
**не прислал ни одного уведомления** ни на ff01, ни на ff03, ни на
альтернативном сервисе, хотя команды доходили (подтверждено `btmon`).
Вероятно, клон игнорирует query-команды и/или не реализует кредиты CX.
Поэтому драйвер должен:

- не блокироваться на ожидании кредитов (fallback — фиксированный темп 30 мс);
- не требовать `0xAA` для успеха (успех = данные отправлены + штатное
  отключение/таймаут);
- корректно работать, если уведомления всё-таки появятся.

## 5. Ограничения и риски

1. Клоны P15 падают/выключаются при пакетах >95 байт (issue #13) — жёстко
   ограничить размер пакета 95 байтами, игнорируя MTU.
2. Принтер может уходить в сон/выключаться — нужен повтор подключения и
   понятная ошибка в CUPS.
3. Нет подтверждения печати от клона — успех определяется по факту передачи.
4. BlueZ может повторно выбрать BR/EDR — helper обязателен при каждом job.
5. Ширина растра должна соответствовать этикетке; не добивать до ширины головы.
6. CUPS запускает несколько job параллельно — нужен lock-файл на BLE.

## 6. Открытые вопросы (нужны данные от пользователя)

- Точный размер этикеток (ширина × высота, мм) и тип (gap/continuous).
- Разрешение печати тестовой этикетки (проверка протокола).
- Нужно ли автоматически создавать очередь и назначать её по умолчанию.
- Один принтер или нужна автоидентификация любых P15/P12/P7.


## 7. Результаты проверки на реальном устройстве

- Печатающая головка: **96 точек (12 мм)**; этикетка идёт на **320 точек
  (40 мм)** вдоль подачи. Растр нужно поворачивать на **270°**.
- Поля: 2 точки с каждой стороны по ширине головки, 2 точки в начале и
  6 точек в конце вдоль подачи (компенсация механического допуска).
- При подключении принтер присылает `01 04` (4 кредита) и `02 DC 00`
  (MTU 220). Уведомления приходят на `ff03`/`ff01`.
- После задания принтер присылает `4F 4B` (`"OK"`); клон подтверждает печать.
- Рабочий размер пакета — **95 байт**, тик **30 мс**; при отсутствии кредитов
  через 1 с выдаётся один принудительный кредит.
- Полный путь CUPS (PDF → pdftoraster → p15-raster → p15 → BLE) проверен:
  этикетка печатается из `lp -d Pristar-P15`.
- BlueZ на этом адаптере (некоторые контроллеры Broadcom) иногда отвечает `Command Disallowed`
  на LE Create Connection; helper посылает `LE Create Connection Cancel`
  перед подключением и повторяет попытку.
